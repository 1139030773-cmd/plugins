# 交互预算规则

> 约束每个技能每次输出时向用户抛出的决策点数量。防止认知过载、注意力分叉、对话失控。

## 通用规则

**每次输出 ≤1 个用户决策点。**

一个"决策点"定义为：需要用户思考后做出选择才能继续推进的问题。

| 不算决策点 | 算决策点 |
|-----------|---------|
| "继续吗？"（推进确认） | "选 A 方案还是 B 方案？" |
| "明白了吗？"（理解确认） | "要不要调整方向？" |
| "准备好了吗？"（状态确认） | "先做哪个功能？" |
| 告知性陈述 | "你觉得这个风险大吗？" |

## 场景豁免：调研同步

**适用技能**：`agent-newbie-guide`（新手引导）

**豁免条件（三项全部满足才触发）**：

| # | 条件 | 说明 |
|---|------|------|
| 1 | **零预期外部信息** | 调研结果来自外部搜索，用户在收到同步前对内容完全无预期 |
| 2 | **层次依赖** | 第二决策依赖第一决策的答案——方向不确定时，聚焦没有意义 |
| 3 | **串行触发** | 用户回答第一问之后，第二问才出现；不是同时抛出 |

**豁免上限**：≤2 个决策点，且必须遵循以下结构：

```
第一决策（方向级）：调研结果是否动摇既定方向？
  ├─ 用户选"调整" → 回到新手引导调整 briefing，不触发第二决策
  └─ 用户选"继续" → 触发第二决策
       └─ 第二决策（聚焦级）：接下来的规划优先关注哪个方面？
```

**格式约束**：

- 第一决策和第二决策**不能在同一轮输出中出现**
- 第二决策只能是"聚焦/排序"类选择（如"先关注哪个竞品""重点看哪个行业"），**禁止**做新方向类决策
- 第二决策触发时，必须用简短的一句话回顾第一决策的结论

**禁止**：

| 禁止行为 | 原因 |
|---------|------|
| 两个并列决策同时抛出 | 认知过载 |
| 第二决策引出第三个决策 | 无边界泛化 |
| 把"聚焦选择"偷换成"方向调整" | 决策层次越界 |
| 其他技能引用此豁免 | 不泛化——仅调研同步场景适用 |

## 违规自检

每个技能在输出前检查：

- [ ] 本次输出有几个需要用户思考后选择的问题？
- [ ] 如果 ≥2，是否满足场景豁免的三项条件？
- [ ] 如果不满足豁免条件，回退到 ≤1

## 偏离处理

同统一行为规范五级纠错体系。交互预算违规属于第 1 级（自查纠正，记录证据链）。
